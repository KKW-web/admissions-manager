# 이음 · 통합 수시진학관리

관리자 입력과 담임의 담당 반 조회를 위한 로컬 검토용 웹앱입니다. Python 3.10 이상에서 실행합니다. 서버 실행에는 추가 패키지가 필요하지 않습니다.

## 실행

Windows에서는 `실행.cmd`를 더블클릭하거나, 명령 창에서 `python launch.py`를 실행합니다. 첫 실행 때 관리자 비밀번호(12자 이상)를 직접 설정합니다. 브라우저에서 `http://127.0.0.1:8765`에 접속하며 계정은 `admin`입니다. 실행 창을 닫으면 앱도 종료됩니다.

담임 계정은 `python server.py user teacher1 teacher 1`처럼 담당 반을 지정해 생성합니다. 현재 담임 조회 범위는 자료학년도 2026, 재학생, 지정 반입니다. 졸업생의 과거 반은 담임에게 노출하지 않습니다. 다음 학년도 운영에는 조회 정책 변경이 필요합니다.

## 데이터와 소스 분리

GitHub에는 프로그램 소스만 저장합니다. `private/`의 DB, 백업, 원본 엑셀, 학생 목록, 스크린샷, 실제 비밀번호는 올리지 않습니다. DB는 저장소 밖 학교 승인 저장 위치에 별도 보관해야 합니다. 현재 구현에서는 앱의 `private/` 폴더를 사용하며 암호화되지 않았습니다.

소스 전용 압축에는 실제 학생 데이터와 계정이 없습니다. 빈 DB로 시작하는 것이 정상입니다. 기존 로컬 앱을 업데이트할 때는 먼저 앱을 종료하고 `private/`를 백업한 뒤 **소스 파일만 교체**합니다. 기존 DB를 빈 DB로 덮어쓰지 마세요. 처음 실행하면 원본에서 보존된 상세값이 구조화되며 관리자 입력은 덮어쓰지 않습니다.

## 화면

지원·합불 현황: 재학구분, 반, 대학, 전형, 학과, 1단계/최종, 수험번호 조건 검색, 열 정렬, CSV 다운로드. CSV는 생년월일을 제외하며 수험번호는 엑셀에서 텍스트 열로 가져와야 앞자리 0이 유지됩니다.

학생 명부: 지원이 없는 학생도 표시. 관리자 학생 등록과 기존 학생의 지원 추가.

데이터 대조: 원본 파일/시트/행과 대조, 병합 근거 기록, 변경 버전 확인, 충돌 차단. 대학명/캠퍼스 차이를 무시하는 신규 자동 병합은 금지합니다. 과거 캠퍼스 생략 결합은 확인 항목으로 표시합니다.

변경 이력: 관리자 저장/병합/검토 이력. 원본 값은 `sources`에 보존됩니다.

상세 화면: 전교과 내신, 지원별 9/5등급, 대학 환산값, 일정, 후보순위, 불합격 사유, 비고, 조회 근거 URL/시각/담당자. 생년월일은 관리자만 선택 표시하며 담임에게는 전송하지 않습니다. 원본 공란은 '미입력'입니다. '미발표'와 구분합니다.

## 검증과 업데이트

`python -m unittest test_regressions -v`와 `node --check static/app.js`를 실행합니다. 회귀 검증은 가상 학생 자료만 사용합니다. GitHub Actions는 소스 검사와 테스트만 수행하며 배포는 수행하지 않습니다. 새 코드는 브랜치/PR에서 검토하고 테스트 후 반영합니다. `.gitignore`와 파일 형식 검사는 민감한 내용의 수동 검토를 대체하지 않습니다.

엑셀 재분석만 `openpyxl`이 필요합니다. 원본 파일은 읽기 전용으로 엽니다. 같은 파일은 해시로 중복 수입을 막습니다. 수정된 엑셀의 증분 갱신은 구현되지 않았으므로 운영 DB에 새 버전을 바로 재수입하면 안 됩니다. 별도 DB에서 대조한 뒤 승인된 변경만 반영하세요.

## 배포 준비

GitHub는 소스와 변경 이력을 보관하는 곳이고, 배포는 별도 서버에서 앱을 실행하는 작업입니다. 이 앱은 Python 서버와 DB를 사용하므로 GitHub Pages에 올리는 방식은 적합하지 않습니다. 학교가 승인한 서버/비공개 서비스, HTTPS, 학교 계정 인증·권한 회수, 암호화·키관리, 백업 복구와 보관 정책이 필요합니다. 현재 Python 표준 HTTP 서버를 인터넷에 직접 노출하지 마세요.

현재 제공한 자동화에는 배포·서버 비밀번호·접속 키가 없습니다. 운영 배포에는 별도 승인이 필요합니다. GitHub 비공개 저장소의 승인 대기 기능은 계정 플랜에 따라 다르므로 가능 여부를 확인한 뒤 구성해야 합니다.

## 합불 조회

아직 대학 사이트 조회 자동화는 없습니다. 대학 공식 URL과 학교의 조회 권한, 사이트별 입력 필드를 확인한 뒤 설계해야 합니다. 결과 공란을 합격/불합격으로 추정하지 않으며 확인 URL·시각·담당자·근거를 지원별로 기록할 수 있습니다. 캡차 우회나 계정 공유는 하지 않습니다. 조회 자체가 대학에 수험번호/생년월일 등을 전송할 수 있으므로 대상 대학과 학생 범위를 먼저 확인해야 합니다.
